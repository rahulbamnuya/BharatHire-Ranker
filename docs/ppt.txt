  Slide 2: Solution Overview

  Proposed solution:

  > BharatHire AI Ranker ranks 100,000 candidates for the Redrob Senior AI Engineer JD using an
  > offline, CPU-only ranking pipeline. It identifies candidates with real production retrieval,
  > ranking, vector search, recommendation, evaluation, and AI engineering experience, then adjusts
  > rank using Redrob behavioral signals.

  Differentiation:

  > Traditional matching checks keywords. Our system evaluates career-history evidence, production
  > context, candidate availability, response behavior, honeypot risk, and factual reasoning. It
  > avoids over-ranking candidates who only stuff AI keywords.

  ———

  Slide 3: JD Understanding

  Key JD requirements:

  - 5-9 years preferred experience.
  - Production AI/ML systems experience.
  - Retrieval, embeddings, vector databases, hybrid search.
  - Ranking, recommendation, search relevance.
  - Evaluation: NDCG, MRR, MAP, A/B testing.
  - Strong Python.
  - Product engineering mindset.
  - Not pure research-only.
  - Not consulting-only background.
  - Candidate should be active and reachable.

  Most important signals:

  - Career history descriptions.
  - Skills and skill duration.
  - Product-company experience.
  - Production deployment language.
  - Ranking/retrieval/evaluation evidence.
  - Recruiter response rate.
  - Last active date.
  - Notice period.
  - GitHub activity.
  - Skill assessments.
  - Honeypot/inconsistency checks.

  ———

  Slide 4: Ranking Methodology

  How retrieve/score/rank:

  > The system streams candidates, removes suspicious profiles, extracts JD evidence from profile and
  > work history text, scores technical fit, adds behavioral availability signals, then sorts by
  > final score.

  Models/algorithms:

  - Weighted evidence ranker.
  - Skill normalization ontology.
  - Honeypot detection rules.
  - Behavioral signal scoring.
  - Deterministic tie-breaking.
  - Optional local embeddings only if cached offline.

  Final score concept:

  Final Score =
  Experience Fit
  + Core AI Skill Evidence
  + Retrieval/Ranking Evidence
  + Production Evidence
  + Evaluation Evidence
  + Product Company Signal
  + Behavioral Availability Score
  - Honeypot / Bad Fit Penalties

  ———

  Slide 5: Explainability & Data Validation

  Explainability:

  > Every selected candidate gets a 1-2 sentence explanation using only real profile facts: title,
  > YoE, employers, skills, response rate, notice period, and last active date.

  No hallucination:

  > We do not use LLM-generated candidate claims. Reasoning is created from structured candidate
  > fields only.

  Suspicious profiles:

  > Honeypot detection checks impossible dates, future jobs, company founding-year violations,
  > excessive expert skills with zero duration, overlapping histories, and experience mismatches.
